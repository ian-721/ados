# Agentic Delivery OS（ADOS）

### 让 AI 持续工作，让人保有控制。

**从一个获批准的决定，走到可以检查和验收的结果。**

[English](README.md) · [系统设计](docs/DESIGN.md) · [研究联系](docs/RESEARCH.md) · [运行示例](#运行参考工具包) · [现状与证据](docs/STATUS.md)

ADOS 是一个本地优先的研究与系统项目，探索如何让 AI 工作跨越会话结束、执行中断和需求变化继续推进。人决定目标、授权重要行动，并验收最终结果；外围系统负责保存这些决定、协调执行、支持恢复和收集证据，而不是把一切都留在 Agent 的对话里。

这里是**赵焱阳（Yanyang Zhao）的 ADOS 设计、参考工具包与完整本地原型源码的公开入口**，包含系统思路、架构、研究联系，以及可运行的 Objective & Evidence Kit。独立脱敏的 [ADOS Local 完整原型源码](prototype/ados-local/README.zh-CN.md) 已公开于 `prototype/ados-local/`。ADOS 还不是生产服务。

## 问题不只是让 Agent 干活，而是让工作持续成立

假设你让 Agent 改进结账页面，保留付款逻辑，交付一个预览，**但不允许部署**。任务进行到一半，会话结束了。随后，你又改了一项需求。

继续工作需要的不只是记住聊天。新的执行者要知道哪些决定仍然有效，哪些工作可以保留，正在修改哪个版本，允许采取什么行动，以及最后如何检查结果。你不应该重新手工整理所有上下文；测试通过也不应该被当成部署许可。

**ADOS 把交付目标，而不是聊天会话，当作持续工作的单位。** 产品目标是减少重复准备、协调、打断、审查和返工，同时保留质量与人的控制权。这些收益仍需在真实使用中测量。

## 系统要承担什么

| 责任 | 具体含义 |
| --- | --- |
| **保持目标明确** | 保存获批准的目标、质量要求、范围和验收条件。 |
| **区分能力与权限** | Agent 能调用工具，不代表它获准这么做。 |
| **把状态放在对话之外** | 保存确认的决定、任务身份、版本引用、恢复状态和证据。 |
| **继续，而不是重来** | 中断后恢复同一项工作；需求经授权改变时，保留仍然有效的部分。 |
| **检查实际发生的事情** | 区分 Agent 自述、独立检查、外部状态回读和可直接体验的产物。 |
| **积累经验，但不自行改写规则** | 经验先评价、再采用；反思和摘要不能自动成为正式规则。 |

这些是系统方向，各部分的实现程度和证据不同，见[当前状态](docs/STATUS.md)。

## 工作如何衔接

```text
人的意图与决定
      ↓
有明确范围的目标 + 显式授权
      ↓
项目真实上下文 + 固定规则版本 + 可恢复状态
      ↓
可替换的 Agent 与工具
      ↓
经过检查的产物 + 证据 ──→ 必要时明确报告阻塞
      ↓
人检查：接受、要求修订，或停止
```

*这是目标交付路径，不代表本仓库已经提供一套安装即可使用的完整系统。*

关键分工是：**人掌握重要决定；Agent 执行委托工作；项目系统保存权威事实；验证检查结果。** 执行者不能自己扩大权限，再自行宣布最终验收通过。

项目自己的 Harness 提供命令、测试、约束和证据要求。模型、Coding Agent 和代码托管平台都是可替换的执行或协作工具。ADOS 不是新基础模型、IDE 或通用 Agent 调度器。

| **WSEOM** | [公开研究议程](https://doi.org/10.5281/zenodo.22992066) | 研究认知工作、经验、验证与行动权如何分配在模型和外围系统之间，不等于完整 ADOS 已有效。 |
| **真实产品部署与广泛连续性** | 尚未证明 | 通用跨设备或跨模型恢复、生产可靠性、经验迁移与实际节省人力，仍需验证。 |

**公开工具包检查记录，不会对正在运行的 Agent 实施权限控制。** 它不认证批准者，不执行记录中列出的测试，不检查所声称的产物，也不确认外部操作是否发生。一个看起来合理的批准字符串可以通过存在性检查。接入前请阅读[安全与信任边界](SECURITY.md)。

## 运行参考工具包

设计的最低语言版本是 **Python 3.10+**；当前公开版本已在 **Linux / Python 3.13.5** 上测试。取得文件后，运行工具包无需第三方 Python 依赖、API Key、模型、账号或联网。

```bash
git clone https://github.com/ian-721/ados.git
cd ados
python tools/ados.py demo
python -m unittest discover -s tests -v
```

系统使用 `python3` 命令时，将 `python` 替换为 `python3`。演示会检查虚构的合法与非法记录，并输出：

```text
Result: 14/14 expected outcomes
```

例如：没有批准引用却从 `IMPLEMENT` 升到 `MERGE`，没有验收引用却宣布 `DONE`，或证据绑定了错误的任务规则，都会被相应检查拒绝。这里检查的是**记录说了什么**，不是实际授权或任务完成的证明。

同时验证目标及其证据：

```bash
python tools/ados.py validate-binding examples/objectives/minimal-objective.json examples/evidence/minimal-evidence.json
```

## 为什么这里也讲研究

ADOS 起源于使用 AI Agent 做产品时遇到的实际问题：如何保留决定、应用过去的指导，以及判断任务是否真正完成。这些问题推动了 **WSEOM——What Should Exist Outside the Model?（模型之外应外置何物？）**。实践提出问题，受控研究则帮助检验系统设计中的假设。

研究议程关心：外部支持何时有帮助、何时造成伤害；哪些经验能够迁移；信息指导与可执行的权限约束有何不同；整个系统是否真的减少了人的工作。它不预设增加记忆、规则或 Agent 数量就一定更好。

因此，ADOS 需要分别测量**决策、证据质量、交付结果、资源成本和人的工作量**。Token 变少不等于总成本降低；引用更准确不等于决策更好；能影响行动的信息，不等于批准行动的权力。
